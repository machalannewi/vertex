# Implementation prompt: My Learning page

## Goal

Build the My Learning page: a per-learner page that reads existing progress and
shows the courses they've started, split into "Continue learning" (in progress,
each with a resume link) and "Completed". Presentational only — it reads
progress for display and has no backend of its own (AGENTS.md §7). The navbar
already links `/my-learning`.

## Decisions confirmed with the user

- **Compose from existing components** (no new visual design): `CourseCard`,
  `ProgressBar`, current page styling (AGENTS.md §3).
- **Two sections**: "Continue learning" (started, <100%, each links to the
  resume lesson) and "Completed" (100%). Empty state links to the catalog when
  nothing is started.

## Decisions & assumptions

1. **Protect `/my-learning` in middleware** (AGENTS.md §7, §12: gate private
   routes in middleware, not client code). Add `createRouteMatcher` +
   `auth.protect()` to `src/proxy.ts`; signed-out users are redirected to
   sign-in. The page then always has a `userId`.
2. **Reuse the progress helpers** `getUserProgress` + `courseProgress` (no new
   write path; read-only).
3. **New additive query `MY_LEARNING_COURSES_QUERY`** returns every course in
   card shape plus `lessons[]{ _id, slug }`, so the page can compute per-course
   progress and resolve the resume lesson's slug for its link. Additive, so it
   doesn't change existing generated types.
4. **"Started"** = any of the course's lessons is completed, has a saved
   position > 0, or has any recorded activity. In progress = started && <100%;
   Completed = 100%.
5. **CourseCard tweak**: when `progressPercent === 100`, show a "Completed"
   label (emerald) instead of "Continue learning". Small, also correct for the
   catalog/instructor grids.
6. In-progress cards link to `/lessons/<resumeSlug>`; completed cards link to
   `/courses/<slug>`. Dynamic page, no `generateStaticParams`/metadata (matches
   existing pages).
7. **TypeGen caveat (same as prior features):** I hand-refresh
   `web/sanity.types.ts` for `MY_LEARNING_COURSES_QUERY_RESULT` since Studio
   TypeGen needs Node ≥22.12 (shell has 22.11); user runs `npm run typegen` in
   `studio/` to confirm (identical diff). A new route's `PageProps` route type
   is generated by `next build`/`next typegen`, so tsc is run after the build.

## Requirements

- Per-learner page showing started courses with progress + a resume affordance;
  reads existing progress, no backend of its own (§7).
- Private route protected in middleware (§7, §12).
- Read-only via the existing server-only read client; the progress read is
  scoped to the current user (§5).
- Responsive to mobile; reuse components; match current styling (§3).

## Security considerations

- No new env vars, tokens, or writes. Progress is read server-side for the
  authenticated user only. Route protection is in middleware.

## Acceptance criteria

- Signed-in `/my-learning`: in-progress courses appear under "Continue learning"
  with a progress bar and a link to the resume lesson; finished courses under
  "Completed"; nothing started → empty state linking to the catalog.
- Signed-out visiting `/my-learning` → redirected to sign-in.
- No regression to catalog/instructor/homepage cards from the CourseCard tweak.

## Checks to run (AGENTS.md §13)

- `web/`: `npm run build` (new route; regenerates route types), then
  `npx tsc --noEmit` and `npm run lint`. Report real output.
- Note `npm run typegen` (Node ≥22.12) to regenerate `sanity.types.ts`
  authoritatively (hand-refreshed here).

## Manual test steps

1. `cd web && npm run dev`, signed in with some progress.
2. Visit `/my-learning` (or click My Learning in the navbar).
3. A started-but-unfinished course shows under "Continue learning" with its
   progress bar; clicking it opens the resume lesson near where you left off.
4. A 100% course shows under "Completed" with a "Completed" label.
5. With no progress, the page shows the empty state linking to `/courses`.
6. Sign out and visit `/my-learning` → redirected to sign-in.
